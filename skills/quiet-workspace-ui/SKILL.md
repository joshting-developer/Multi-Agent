# Multi-Agent 介面文案

此專案是日常使用的 VS Code 開發工具。以目前使用者的明確偏好為準：讓介面呈現工作、選項及結果，避免用說明段落介紹介面本身。

## 判斷文字是否需要

- 會影響當下選擇的資訊才留在主畫面：模型名稱、推理強度、帳號、權限、執行狀態、可操作的錯誤。
- 控制項以位置、名稱、圖示與狀態表達用途。不要再加一句重述標籤或按鈕的操作教學。
- 歷史為空時可以直接留白並保留新增入口。不加「過去的對話紀錄會出現在這裡」「開始聊天後會保存在這裡」。搜尋無結果、載入中、失敗則顯示簡短且真實的狀態。
- 不用文字填滿空間，不顯示歡迎文、功能推銷、未實作的功能或預告。
- API 名稱、SQLite、傳輸協定、資料來源及 CLI 版本屬於技術細節，放文件或「進階」展開區；僅在排錯或選擇依賴它時顯示。
- 設定的標籤已說清楚用途，就移除附帶的重複說明。欄位單位、必要格式與不可消除的限制仍放在欄位附近。
- 成功回饋簡短，例如「已儲存」。錯誤說明原因與下一步，不用一般性長篇提醒。

## 不可因精簡而省略

- 模型與推理強度使用明確值，不能以「預設」隱藏實際選擇。
- 權限擴大、不可還原刪除、資料跨 Provider 傳送等決策所需的影響與確認。
- 可見的欄位名稱、圖示按鈕的可存取名稱、鍵盤焦點、載入／錯誤狀態。
- 模型別名仍標示為別名，未知帳號或不支援能力不可假裝已取得。

## 套用方式

檢查聊天、空白歷史、搜尋無結果、設定與錯誤狀態。逐句問：「刪掉後，使用者會做錯當下的選擇嗎？」不會就刪除；只在少數情境需要的資訊移到展開區。完成後用實際 Webview 檢查操作入口、窄側邊欄與狀態仍可辨識。文字刪減不需要建立逐句比對測試。
