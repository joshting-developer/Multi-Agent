# MA-76 本機 Embedding 與混合檢索評估

日期：2026-11-14。規格 §8 第三階段，前置為 M3／M4。

## 結論

- 目前不做。卡片的第一個條件「先有可重現的查詢品質基準」還無法成立：真實歷史只有 248 KB，M4 的經驗卡也還沒有，拿合成資料做出來的基準沒有參考價值。
- 字面搜尋目前沒有不足的證據，見 [MA-40](fts-search.md)。語意檢索要解決的是「用不同說法描述同一個問題」，必須先累積真實查詢失敗案例才能判斷是否需要。

## 若要做的方向

| 項目 | 建議 |
| --- | --- |
| 模型 | 本機多語模型，例如 multilingual-e5-small 等級（約 384 維），以 ONNX／WASM 在 Extension Host 執行，不呼叫外部 API |
| 範圍 | 只對 M4 的經驗／決策卡和討論結論做向量化，不對全部原始訊息做 |
| 儲存 | 向量以 BLOB 存在同一個 SQLite，以 JS 計算餘弦相似度；sql.js 沒有 `load_extension`，無法使用 sqlite-vec |
| 合併 | 字面搜尋＋向量＋Tag／時間／專案範圍，以 RRF 合併排序，每筆結果都附上來源 message ID |
| 降級 | 模型沒下載或載入失敗時，只用字面搜尋，不影響一般使用 |

成本：模型檔約數十到上百 MB，不應打包進 VSIX，要讓使用者明確選擇下載。1 萬張卡 × 384 維 × 4 bytes 約 15 MB，暴力搜尋可行；原始訊息全量向量化則不合理。

外部 Embedding 服務屬於資料外送，必須走 workspace 資料政策的明確授權，預設關閉。

## 啟動條件與基準

M4（MA-47～50）上線並累積實際資料後，從真實使用中收集至少 30 組「查得到但字面搜尋找不到」的查詢，建立固定的查詢—期望結果集，量測 Recall@5。字面搜尋明顯不足時再開實作卡，沿用本卡原驗收條件。
